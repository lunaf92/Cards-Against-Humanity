# Phase 3: WebSocket Room Protocol and Events

This document defines the real-time protocol for room and gameplay events.

## Status

- Protocol version: `v1`
- Transport: WebSocket (JSON messages)
- Scope: lobby, matchmaking lifecycle, game loop, reconnect sync

## Endpoint and Authentication

- Endpoint: `GET /ws/rooms/{room_id}?token=<access_jwt>`
- Auth method: JWT query parameter at connect time
- Authorization rule: user must be a room member (or be added by matchmaking flow)
- Server behavior on auth failure: close socket with code `4401`

### Browser clients

- Browsers cannot set an `Authorization` header on a WebSocket, which is why the
  access token travels in the `token` query parameter:
  `new WebSocket(`${wsBase}/ws/rooms/${roomId}?token=${accessToken}`)`.
- Use `ws://` when the page is served over `http://` and `wss://` behind a
  TLS-terminating reverse proxy. The proxy must forward the `Upgrade` /
  `Connection` headers for `/ws/` and should not time out idle sockets sooner
  than the client pings (`client.ping`, e.g. every 25 s).
- The server always *accepts* the socket before rejecting it, so a browser sees
  an `error` event followed by `close` with the application close code below
  (not a bare `1006`).
- `CORS_ORIGINS` (JSON list, env) only governs the REST API. WebSocket
  connections are authenticated by the token alone.
- A token is only checked at connect time; an open socket survives token expiry.

Recommended close codes:
- `1000` normal closure
- `4401` unauthorized (invalid/expired token)
- `4403` forbidden (not a room member)
- `4404` room not found
- `4409` conflict (duplicate active connection policy, optional)
- `1011` internal server error

## Message Envelope

All inbound and outbound messages use the same envelope.

```json
{
  "version": "v1",
  "event": "room.player_joined",
  "room_id": "7fcbf5f4-0f53-4e6c-bc30-3fa3b95689cb",
  "message_id": "3bb5c4df-d09a-4f73-a02a-e1de4f3e9c89",
  "timestamp": "2026-04-26T12:30:45.812Z",
  "correlation_id": "f7fb24ea-0f73-4545-a672-0809bb0a97f3",
  "payload": {}
}
```

Envelope fields:
- `version`: protocol version string, currently `v1`
- `event`: event name
- `room_id`: UUID of room channel
- `message_id`: UUID generated by sender
- `timestamp`: ISO-8601 UTC timestamp
- `correlation_id`: optional UUID linking request and response/ack
- `payload`: event-specific object

## Client -> Server Commands

### client.ping
Purpose: keepalive and RTT measurement.

Payload:
```json
{ "sent_at": "2026-04-26T12:30:45.812Z" }
```

Server response: `server.pong`

### room.state_sync.request
Purpose: request full room/game snapshot after reconnect.

Payload:
```json
{}
```

Server response: `room.state_sync`

### lobby.start_game
Purpose: host starts game in private lobby.

Guards:
- requester is host
- room status is `lobby` or `matchmaking_lobby`, or the room is a random room
  that the matchmaking worker already locked (`in_progress` with no round yet)
- player count >= 3

Payload:
```json
{}
```

Server response on success: `game.started`

### game.submit_cards
Purpose: non-Czar submits white cards for current round.

Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "white_card_ids": [
    "6f8f0f51-f2da-4e16-8f4f-6b5d31b1f020"
  ]
}
```

Guards:
- requester is in room and connected
- requester is not Czar
- card count equals black card `pick`
- cards exist in requester hand

Server success event: `round.submission_accepted`

### game.pick_winner
Purpose: Czar selects winner from anonymized submissions.

Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "submission_id": "08925f4f-a693-45c6-ad57-84dbfc2433ea"
}
```

Guards:
- requester is current Czar
- round status is `judging`

Server success event: `round.result`

### room.reaction
Purpose: send a quick reaction (emoji or stock phrase) to everyone in the room.

Payload:
```json
{ "reaction_id": "oh_come_on" }
```

Guards:
- `reaction_id` is one of: `laugh`, `fire`, `grimace`, `sick`, `clap`, `facepalm`,
  `nice_one`, `oh_no`, `hurry_up`, `oh_come_on`, `regret_nothing`, `gg`
  (else `INVALID_PAYLOAD`). No free text.
- at most one reaction per player every 2 s (else `RATE_LIMITED`, with
  `details.retry_after` in seconds).

Server success event: `room.reaction` broadcast to the room (sender included),
payload `{ "player_id": "<uuid>", "reaction_id": "oh_come_on" }`. Nothing is stored.
The client maps ids to the emoji or text it shows.

## Server -> Client Events

### Connection and Sync

#### room.connected
Sent to caller after successful auth and room membership validation.

Payload:
```json
{
  "user_id": "f5bf8580-a8b7-454f-8610-194ffd04f26d",
  "room_status": "lobby"
}
```

#### room.state_sync
Full state snapshot for initial connect or explicit sync request.

Payload:
```json
{
  "room": {
    "id": "7fcbf5f4-0f53-4e6c-bc30-3fa3b95689cb",
    "code": "AB12CD",
    "room_kind": "private",
    "status": "lobby",
    "host_id": "f5bf8580-a8b7-454f-8610-194ffd04f26d",
    "max_players": 10,
    "winning_score": 8,
    "round_timer_seconds": 90,
    "decks": [
      { "id": "uuid", "name": "Base Game", "is_builtin": true, "is_public": true, "black_count": 80, "white_count": 502 }
    ],
    "matchmaking_fill_expires_at": null
  },
  "players": [
    {
      "player_id": "f5bf8580-a8b7-454f-8610-194ffd04f26d",
      "username": "host",
      "join_order": 1,
      "score": 0,
      "is_connected": true
    }
  ],
  "game": null
}
```

`game` is `null` unless a round is active (`waiting` or `judging`). While a round
is active it is everything a client needs to render the table after a (re)connect
or page reload:

```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "round_number": 3,
  "status": "waiting",
  "czar_id": "6fd6f46d-7a3d-4d4a-9fa8-cbeac13f1986",
  "submitted_count": 1,
  "required_count": 3,
  "submitted_player_ids": ["f2a9ca2f-6be8-46b7-951b-20f0f07f830f"],
  "has_submitted": false,
  "black_card": { "id": "3c6bce6a-...", "text": "Why can't I sleep at night?", "pick": 1 },
  "hand": ["6f8f0f51-f2da-4e16-8f4f-6b5d31b1f020"],
  "hand_cards": [
    { "id": "6f8f0f51-f2da-4e16-8f4f-6b5d31b1f020", "text": "A mime having a stroke." }
  ],
  "phase_expires_at": "2026-04-26T12:32:48.100Z"
}
```

- `hand` / `hand_cards`: the requesting player's own hand (ids only / ids with text).
- `has_submitted`, `submitted_player_ids`: who has already played this round.
- `submissions`: present only when `status` is `judging`; same shape as in
  `round.judging`. The order is stable across repeated syncs.
- `phase_expires_at`: deadline of the running submission or judging timer, or
  `null` when no timer is armed.

### Lobby Presence

#### room.player_joined
Payload:
```json
{
  "player": {
    "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
    "username": "player2",
    "join_order": 2,
    "score": 0,
    "is_connected": true
  }
}
```

#### room.player_left
Payload:
```json
{
  "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "reason": "disconnect"
}
```

#### room.host_changed
Payload:
```json
{
  "previous_host_id": "f5bf8580-a8b7-454f-8610-194ffd04f26d",
  "new_host_id": "6fd6f46d-7a3d-4d4a-9fa8-cbeac13f1986"
}
```

#### room.config_updated
Sent after the host changes settings with `PATCH /rooms/{room_id}/config`.
`room` has the same shape as `room.state_sync`'s `room`.

Payload:
```json
{ "room": { "id": "7fcbf5f4-...", "max_players": 8, "winning_score": 5, "round_timer_seconds": 60, "...": "..." } }
```

### Matchmaking Lifecycle

Players queued with `POST /rooms/queue` have no room socket yet, so only the
player whose request completed the match learns the room id from the response.
Everyone else polls `GET /rooms/active` (every 2-3 s) until it returns a room,
then connects to that room's socket. The same endpoint lets a client resume its
unfinished room after a page reload.

#### matchmaking.match_found
Emitted to matched players once they are assigned to a random room.

Payload:
```json
{
  "room_id": "7fcbf5f4-0f53-4e6c-bc30-3fa3b95689cb",
  "player_count": 3
}
```

#### matchmaking.countdown_started
Payload:
```json
{
  "expires_at": "2026-04-26T12:31:10.000Z",
  "seconds_remaining": 10,
  "player_count": 3
}
```

#### matchmaking.countdown_reset
Payload:
```json
{
  "expires_at": "2026-04-26T12:31:18.000Z",
  "seconds_remaining": 10,
  "player_count": 4
}
```

#### matchmaking.countdown_canceled
Payload:
```json
{
  "reason": "player_count_below_minimum",
  "player_count": 2
}
```

#### matchmaking.locked
Sent when lobby closes and game can start.

Payload:
```json
{
  "reason": "timer_expired",
  "player_count": 4
}
```

Allowed `reason` values:
- `timer_expired`
- `max_players_reached`

### Game Lifecycle

#### game.started
Payload:
```json
{
  "started_at": "2026-04-26T12:31:18.100Z",
  "round_number": 1,
  "players": [
    {
      "player_id": "f5bf8580-a8b7-454f-8610-194ffd04f26d",
      "score": 0
    }
  ]
}
```

#### round.started
Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "round_number": 1,
  "czar_id": "6fd6f46d-7a3d-4d4a-9fa8-cbeac13f1986",
  "black_card": {
    "id": "3c6bce6a-8d95-4283-99a5-c9e6c84be7bc",
    "text": "Why can't I sleep at night?",
    "pick": 1
  },
  "round_expires_at": "2026-04-26T12:32:48.100Z"
}
```

#### player.hand
Personal event (only sent to the owning player) right after every
`round.started`, carrying that player's current hand. Clients that miss it get
the same data from `room.state_sync` (`game.hand_cards`).

Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "hand": [
    { "id": "6f8f0f51-f2da-4e16-8f4f-6b5d31b1f020", "text": "A mime having a stroke." }
  ]
}
```

#### round.submission_accepted
Sent to submitter (personal event) and optionally as aggregate update to room.

Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "submitted_count": 2,
  "required_count": 3
}
```

#### round.timer_expired
Informational: the submission timer ran out. Idle players were auto-submitted
(as many cards as the black card's `pick`). Followed by `round.judging`, or by
`round.started` when nobody had any submission and the round was skipped.

Payload:
```json
{ "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950" }
```

#### round.judging
Sent when all submissions are in, when the timer auto-submits unresolved
players, or when the last player who had not submitted is removed by a
reconnect timeout.

Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "submissions": [
    {
      "submission_id": "08925f4f-a693-45c6-ad57-84dbfc2433ea",
      "white_card_texts": ["A mime having a stroke."]
    }
  ],
  "judging_expires_at": "2026-04-26T12:34:18.100Z"
}
```

#### round.judging_expired
Informational: the czar did not pick in time and a random winner was chosen.
Followed by the normal `round.result` sequence with `correlation_id = null`.

Payload:
```json
{ "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950", "reason": "czar_timeout" }
```

#### round.result
Payload:
```json
{
  "round_id": "4fbf1bb8-c2fd-42b4-a8f2-51230d3da950",
  "winner_player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "winning_submission_id": "08925f4f-a693-45c6-ad57-84dbfc2433ea",
  "scores": [
    {
      "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
      "score": 1
    }
  ]
}
```

If the winning submission's author was removed from the room in the meantime,
the round still resolves: `winner_player_id` names the departed player and no
score changes.

#### game.over
Payload:
```json
{
  "winner_player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "reason": "winning_score_reached",
  "scoreboard": [
    {
      "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
      "score": 8
    }
  ]
}
```

`reason` values:
- `winning_score_reached` — `winner_player_id` is the winner.
- `not_enough_players` — a reconnect timeout left fewer than 3 players;
  `winner_player_id` is `null` and `scoreboard` holds the final scores.

### Reconnect and Timeout

#### player.reconnect_window_started
Payload:
```json
{
  "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "expires_at": "2026-04-26T12:35:00.000Z",
  "seconds_remaining": 60
}
```

#### player.reconnected
Payload:
```json
{
  "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f"
}
```

#### player.removed_timeout
Payload:
```json
{
  "player_id": "f2a9ca2f-6be8-46b7-951b-20f0f07f830f",
  "reason": "reconnect_timeout"
}
```

Sent when a player is still disconnected after the reconnect window
(`RECONNECT_WINDOW_SECONDS`, default 60). The player is removed from the room.
Depending on the game state it may be followed by `room.host_changed` (the host
left), `round.judging` (everyone remaining had already submitted),
`round.started` (the czar left; the round is skipped) or `game.over` with
`reason = "not_enough_players"`.

### Utility

#### server.pong
Payload:
```json
{
  "sent_at": "2026-04-26T12:30:45.812Z",
  "received_at": "2026-04-26T12:30:45.920Z"
}
```

#### error
Payload:
```json
{
  "code": "NOT_HOST",
  "message": "Only host can start the game",
  "details": {
    "event": "lobby.start_game"
  }
}
```

## Error Codes

Common protocol-level error codes:
- `UNAUTHORIZED`
- `FORBIDDEN`
- `ROOM_NOT_FOUND`
- `INVALID_EVENT`
- `INVALID_PAYLOAD`
- `NOT_HOST`
- `GAME_NOT_STARTED`
- `ROUND_NOT_ACTIVE`
- `NOT_CZAR`
- `INVALID_CARD_SELECTION`
- `DUPLICATE_SUBMISSION`
- `STATE_CONFLICT`
- `RATE_LIMITED`
- `INTERNAL_ERROR`

Error handling notes:
- A frame that is not a JSON object (or whose `payload` is not an object) is
  answered with `INVALID_PAYLOAD`; the socket stays open.
- An unexpected server-side failure while handling a command is answered with
  `INTERNAL_ERROR` (carrying the command's `correlation_id`); the socket stays
  open and the client should send `room.state_sync.request`.
- Clients must ignore events they do not know, so new events can be added.

## Ordering and Idempotency Rules

- Client commands should include `message_id` and optional `correlation_id`.
- Server responses for state-changing commands should include same `correlation_id`.
- Duplicate command `message_id` from same user and room should be treated idempotently when possible.
- Event ordering is guaranteed per room channel from the server process; cross-instance ordering must rely on Redis pub/sub sequence discipline.

## Minimum Backend Implementation Contract

- Reject unauthorized connects with close code `4401`.
- Emit `room.connected` then `room.state_sync` on successful connect.
- Emit lobby presence events (`room.player_joined`, `room.player_left`, `room.host_changed`).
- Emit matchmaking lifecycle events:
  - `matchmaking.match_found`
  - `matchmaking.countdown_started`
  - `matchmaking.countdown_reset`
  - `matchmaking.countdown_canceled`
  - `matchmaking.locked`
- Support commands:
  - `room.state_sync.request`
  - `lobby.start_game`
  - `game.submit_cards`
  - `game.pick_winner`

## Compatibility Notes

- This protocol maps to existing room states and fields already in place:
  - `room_kind`
  - `status`
  - `matchmaking_fill_expires_at`
- Matchmaking countdown events should be sourced from worker-driven state transitions to stay server-authoritative.
